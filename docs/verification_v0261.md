# v0.26.1 語法修正與驗證更正

日期：2026-10-10。

## 已確認的錯誤

使用者回報後，我們確認原 v0.26 ZIP 的 `lib/presentation/screens/victory_screen.dart` 第26–27行，在普通單引號字串內插入了實體換行。Dart 不允許這種寫法，造成 `Unterminated string literal` 與後續連鎖錯誤。修正為字串內的 `\n` 跳脫字元，顯示文字與換行意圖不變。

修正前對該檔直接執行 `dart format --output=none`，實際退出碼為65。先前「98檔解析通過」的驗證結論錯誤，撤回該結論。先前流程沒有把解析失敗當成阻止交付的閘門；檔案數量與 domain 測試通過不能證明 UI 檔案語法正確。另找到原始解析日誌：中段確實記錄此字串錯誤，末行仍寫「Formatted 98 files」。該數字是成功處理的檔案數，不代表所有檔案成功；先前錯讀摘要且沒有以退出碼作交付閘門。沒有找到原始命令的完整退出碼處理，因此不臆測是特定管線造成。

修正後獨立逐檔檢查100個Dart檔（lib62、test30、tools8），每次parser退出碼均為0；故意插入非法換行的回歸樣本正確被拒絕（exit65）。

## 新的防線

`tools/verify_dart_syntax.dart` 逐一呼叫真正的 Dart formatter/parser，检查每個退出碼；任何非零值都使整體失敗。它先建立包含相同非法換行的臨時程式，確認 parser 確實拒絕（exit65），然後解析 lib、test、tools 所有 Dart 檔。這個檢查已加入 `tools/verify_all.dart`，在六套規則測試之前執行。

封裝後會重新解開累積 ZIP 合併至 v0.25 原始交付包，再對實際交付內容執行同一檢查。小修正包另合併至 v0.26 原始交付包檢查。逐檔退出碼必須全部為0才可交付。

## 範圍

此次不改遊戲規則、資產、依賴鎖檔、schema8 或存檔隔離 key。Flutter 指令仍因先前工具限制未於此環境執行；不把純 Dart 語法通過當成 Flutter 型別檢查、建置或 UI 驗收通過。使用者已提供其環境依賴解析成功的紀錄，但不代表此修正後應用程式已由我們實機運行。
